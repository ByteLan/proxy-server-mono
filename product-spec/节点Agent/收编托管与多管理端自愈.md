# 收编托管与多管理端自愈

## 1. 业务规则（当前生效）

- **双模式节点接入**：
  1. **方案 A — 存量内核无感收编（`adopt` / `--adopt-existing`）**：针对已通过 systemd 运行 `hysteria.service` 与/或 `xray.service` 的存量主机，只读解析 `/etc/hysteria/config.yaml`（提取端口、密码、SNI、证书 SHA-256 指纹）与 `/etc/xray/config.json`（支持 JSONC 注释，由 REALITY 私钥推导客户端公钥，并支持导入 `vless`、`socks5`、`http`、`https` 入站），生成仅含 `services` 列表而不含 `commands` 的 `config.json`。不覆盖原有内核二进制，不中断已有连接。
  2. **方案 B — 纯新机器全协议子进程托管（`init`）**：在空机器上生成随机节点 ID、自签证书、Hysteria2 配置与多入站 Xray 配置（`config.d/`，`0600`），默认一次性初始化 `Hysteria2`（UDP `443`）、`VLESS-REALITY`（TCP `443`）、`SOCKS5`（TCP+UDP `1080`）、`HTTP`（TCP `8080`）与 `HTTPS`（TLS `8443`，复用节点证书 SHA-256 指纹）共 5 种协议（`--socks5-port` / `--http-port` / `--https-port` 传 `0` 可单独关闭），随 `proxy-server.service` 开机自动启动并由 `proxy-server` 作为父进程直接托管并监控两个核心子进程。
- **多管理端并发上报（Multi-Manager）**：单个 `proxy-server` 支持通过 `add-manager` / `list-managers` / `remove-manager` 配置至多 16 个独立 `proxy-manage-server`（保存在 `managers[]`，各自独立持有 `ca_file`、`enroll_token` 与 `config.d/manager_<hash>.token`）。各管理端注册与心跳协程完全隔离，任一管理端故障不影响其余管理端上报。
- **后台删除后自主重登与黑名单屏蔽隔离**：管理员在后台点击「删除」移除节点（或从黑名单「解除屏蔽」）后，对应管理端在下次心跳返回 `410 Gone`，`proxy-server` 无需重启或人工介入，立即使用该管理端对应的 `ENROLL_TOKEN` / `enroll_token` 重新调用 `/api/agent/register` 获取新节点 Token 并补发全量 `endpoints` 心跳，自动恢复在线展示；若管理员点击「屏蔽」将节点移入黑名单，心跳返回 `401`（注册返回 `409`），`proxy-server` 保持本地代理核心稳定运行并退避等待，绝不绕过黑名单重连。
- **开机启动顺序与弱依赖隔离**：`--adopt-existing` 安装时自动生成 `/etc/systemd/system/proxy-server.service.d/adopted-cores.conf`，声明 `Wants=<units>` 与 `After=<units>`：冷启动时先拉起代理内核再启动 `proxy-server`；内核运行期异常停止时不会反向拖死 `proxy-server`。
- **指数退避自愈（上限 10 次）与无 `polkitd` 最小权限拉起**：
  - 无论子进程模式（存活不足 1 分钟视作异常崩溃）还是收编模式（`systemctl is-active` 探测为非活跃），`proxy-server` 主进程**绝不因内核未运行而崩溃退出**，而是执行指数退避拉起，**连续失败最多尝试 10 次**。
  - 收编模式下，针对 `User=proxy-node`（`NoNewPrivileges=true`）且云镜像普遍无 `polkitd` 的限制，安装器自动部署 root 级 `proxy-server-recover-<slug>.{path,service}`，监听 `/etc/proxy-server/recover/<unit>.trigger` 触发受限 `systemctl start <unit>`，并由 `ExecStopPost=-/bin/rm -f` 删除触发文件作为完成信号。
  - 一旦内核恢复健康运行，连续失败计数立即归零；若连续 10 次仍失败，停止继续拉起并在心跳 `CoreStatus.Error` 中持续上报 `gave up after 10 recovery attempts`。

## 2. 跨端代码锚点

- **CLI 子命令入口**：`cmd/proxy-server/main.go`（`init`、`adopt`、`run`、`add-manager`、`remove-manager`、`list-managers`、`update`）
- **存量配置收编解析**：`internal/agent/adopt.go`
- **多管理端增删查**：`internal/agent/managers.go`
- **心跳循环与配置热重载**：`internal/agent/run.go`
- **子进程监控与外部 systemd 退避自愈**：`internal/agent/supervisor.go`（`supervisor`、`serviceMonitor`、`startSystemdService`）
- **节点安装与恢复单元生成脚本**：`scripts/install-proxy-server.sh`、`deploy/systemd/proxy-server.service`

## 3. 模块红线

- 收编模式（`--adopt-existing`）严禁与核心二进制安装参数混用，严禁覆盖或重启宿主机既有内核二进制及配置文件。
- `proxy-server.service` 对外部内核单元严禁使用 `Requires=` 或 `BindsTo=` 强绑定；严禁为实现拉起而给 `proxy-node` 赋予宽泛 `sudo` 或移除 `NoNewPrivileges=true`。
- 节点与远端管理端通信强制要求 HTTPS 并验证服务端证书（私有 CA 通过 `--ca-file` 注入根证书池），仅本机回环开发允许显式 `--allow-insecure-http`。
